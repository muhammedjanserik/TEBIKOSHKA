# Tebikoshka — қазақша дебат турнирін басқару

Python 3.11+ қажет. Сыртқы кітапхана, Node.js немесе бөлек дерекқор сервері қажет емес.

## Іске қосу

Осы папкадағы терминалда:

```sh
python3 app.py
```

Браузерде **http://127.0.0.1:8000** ашыңыз. «Аккаунт ашу» сілтемесін басып, логин мен кемінде 6 таңбалы пароль енгізіңіз. Алғашқы аккаунт та осылай жасалады. Серверді тоқтату: `Ctrl+C`.

Басқа порт қажет болса: `PORT=8001 python3 app.py`.

## Жұмыс тәртібі

1. «Баптаулар» бетінде атауды, АПФ/БПФ форматын, раунд санын, High/Low режимін таңдаңыз. «Сақтау және тіркеуге өту» батырмасын басыңыз. High/Low таңдалмаса немесе «Тек алдыңғы раунд» режимінде ешбір раунд белгіленбесе, «Қолданбау» сақталады.
2. «Тіркеу» бетінде «Фракциялар» және «Төрешілер» қойындыларын кез келген ретпен толтырыңыз. Қойынды ауыстыруға құрам саны шектеу қоймайды.
3. «Тіркеуді аяқтау» кезінде БПФ құрамы кемінде төрт және төртке бөлінетін болуы керек; әр төрт фракцияға бір төреші қажет. АПФ-да әр жұпқа бір төреші қажет, тақ құрамның автожеңісін растаңыз. Автожеңіске рум мен төреші есептелмейді. «Турнирді бастау» осы шарттарды қайта тексеріп, бірінші жеребені ашады.
4. Жеребеде фракцияларды сүйреп орын алмастырыңыз. Төмендегі бос төрешілерді румдарға апарыңыз. «Босату» төрешіні бос тізімге қайтарады. Кабинеттер келесі раундқа көшіріледі. Өңдеулер серверде сақталады.
5. Әр румға кемінде бір төреші тағайындап, жеребені растаңыз. Кестедегі рум жолын басып, нәтижелерді енгізіңіз. Автожеңіс үшін де екі спикер балын енгізіңіз.
6. Барлық нәтиже сақталған соң келесі раундқа немесе рейтингтерге өтіңіз.
7. Соңғы іріктеу раундының барлық нәтижесі сақталғаннан кейін қорытынды рейтингте «Турнирді аяқтау» қолжетімді болады. Бұрын сақталған плей-офф белгісі аяқтауға әсер етпейді. «Турнирді аяқтау» арқылы парольді енгізіп, екі парақты Excel жүктеңіз. Файлды сақтаған соң ғана «Файлды алдым, турнирді аяқтау» батырмасын басыңыз.

Экспорт сәтсіз болса, турнир сақталады: қайта жүктеуге болады. Соңғы растау турнирді өшіреді, аккаунтты сақтайды. Жүктеу сілтемесі сол диалогта қайта жүктеуге мүмкіндік береді; бетті қайта ашсаңыз, экспортты қайта жасаңыз.

## Деректер және қауіпсіздік

`tab.sqlite3` автоматты түрде жасалады. Браузер немесе сервер қайта іске қосылғанда деректер сақталады. Серверді тоқтатып, осы файлды көшіріп сақтық көшірме жасауға болады. Дерекқор жолын `TAB_DB=/path/to/tab.sqlite3 python3 app.py` арқылы таңдауға болады.

Парольдер кездейсоқ тұзбен scrypt арқылы хэштеледі. Серверлік сессиялар 7 күн сақталады, cookie HttpOnly және SameSite=Strict. Аккаунт тек өз турнирін көреді. Бір аккаунтта бір турнир шектеуі SQLite кестесінде де бар. SQLite транзакциясы мен revision тексерісі қатар өңдеуді және қос раунд жасауды болдырмайды. Ескірген бет туралы хабар шықса, бетті жаңартыңыз.

Сервер жергілікті компьютердің 127.0.0.1 мекенжайында жұмыс істейді. Ортақ аккаунтты басқа компьютерлерден қолдану үшін HTTPS бар өндірістік серверге бөлек орналастыру қажет.

Жеребе бірнеше жарамды нұсқаны салыстырады: High/Low бойынша жақын нәтиже, позициялардың теңдігі, содан кейін қарсыластардың аз қайталануы. Мінсіз жеребеге кепіл берілмейді. Тарихқа тек расталған жеребе кіреді. Автожеңіс тарихы позициялар мен қарсыластардан бөлек есептеледі.

Ортақ орындар 1, 1, 3 тәртібімен көрсетіледі. Плей-офф сеткасы, брейкті шешу және Линкольн–Дуглас іріктеуі осы нұсқаға кірмейді.

## Тексеру

```sh
python3 -m unittest discover -s tests -v
```

HTTP тесттері уақытша SQLite пен жергілікті портты пайдаланады; негізгі турнир деректерін өзгертпейді. АПФ және БПФ толық барысы, тақ құрамның автожеңісі, БПФ құрам саны, төреші минимумы (64 фракцияны қоса), толық емес нәтижені қабылдамау, тең рейтингтер, төрт БПФ позициясының теңдігі, екі қатар сұраныс, аккаунттардың оқшаулануы, қайта кіру, Excel құрылымы және экспорт қатесінен кейін сақталу тексеріледі.

Дизайн Chrome браузерінде 1440, 390 және 320 px енінде тексерілді: бастапқы бет, тіркелу, жергілікті SVG файлдары және «Турнир жасау» → баптау беті. Скриншоттар `artifacts/` папкасында сақталған. Сүйреп апару төмендегі Chrome сценарийінде тексеріледі; файл жүктеуді браузерде бөлек тексеріңіз. Телефонда карточкаларды сүйреу браузер қолдауына тәуелді; жеребені компьютерде өңдеу ұсынылады.

Қойынды атауы, тіркелу, жергілікті SVG файлдарының жүктелуі тексерілді; JavaScript қатесі шықпады. `python3 -m unittest discover -s tests -v`: 6 тест өтті. Тексерулер бөлек уақытша дерекқорларда жүргізілді; негізгі `tab.sqlite3` өзгертілмеді.

## Фракциялар, жеребе және нәтижелерді жаңарту — 2026-11-11

- Баптауда фракцияны атауын көрсететін растаумен жоюға болады. Сервер тек осы аккаунттың, әлі басталмаған турниріндегі фракцияны жояды. Сан өзгергенде келесі қадамның қолжетімділігі қайта есептеледі.
- Клуб өрісіндегі ұсыныстар осы турнирде енгізілген клубтардан алынады; тінтуірмен немесе төмен бағыттауыш пен Enter арқылы таңдауға болады. Басқа жұмыс өрістерінде `autocomplete="off"`. Кіру/тіркелуде `username`, `current-password`, `new-password` қолданылады.
- Жеребе ықшамдалды. Оң жақтағы бос төрешілер панелі экранда қалады, ұзын тізімі бөлек айналады. Сүйреу және румдағы тағайындау тізімі бір серверлік сақтау жолын қолданады; бірнеше төреші қосу мен босату сақталды.
- АПФ нәтижесінде бір жеңімпаз таңдалады. БПФ рангтері бірегей; босатылған ранг қайта қолжетімді. Қате қазақша нәтиже терезесінің ішінде шығады, мәндер сақталады. Кең экранда спикер балдары қатар орналасады; тар экранда терезе айналып, әрекет батырмалары көрініп тұрады.

Тексеру: `python3 -m unittest discover -s tests -v` — 8 тест өтті. Оған аккаунттар арасындағы жоюды қабылдамау, 49 → 48 фракция, басталған турнирде жоюға тыйым, қайталанған төрешіні және қате балдарды қабылдамау кіреді.

Chrome сценарийі `tests/browser_check.py` файлында сақталды. Playwright пен Google Chrome орнатылған Python ортасында, **бөлек сынақ серверін** іске қосыңыз:

```sh
TAB_DB=/private/tmp/tebikoshka-features.sqlite3 PORT=8018 python3 app.py
# Екінші терминалда:
python tests/browser_check.py
```

Chrome тексерісі өтті: жоюдан бас тарту/растау және 49 → 48-мен келесі қадам; клуб ұсынысын пернетақтамен таңдау; өзге өрістердің autocomplete параметрлері; 12 румдық жеребенің жоғарысы мен төменіне нақты тінтуір қозғалысымен сүйреу және тізімнен тағайындау; бірнеше төреші, босату, панель мен оның тізімінің айналуы; 390 px экранда басып тағайындау; АПФ жеңімпазы, әр спикердің балдары, автожеңіс; БПФ рангін қайталатпау және босатқанда қайта ашу; бос өріс, теріс балл, нақты сервер қайтарған қате кезінде терезе мен мәндердің сақталуы; сақталған нәтижені қайта ашу. JavaScript қатесі жоқ. 1366×768 экранында БПФ-ның төрт блогы мен сақтау батырмасы экранға сыяды. Скриншоттар `artifacts/draw-*.png` және `artifacts/result-*.png` ішінде.

Браузер тексерісі таза Chrome контексінде жасалды: жеке Chrome профилінің бұрын сақталған форма тарихы мен пароль менеджерінің қалқымалы терезелері тексерілген жоқ. Жұмыс өрістерінің браузерлік тарихын өшіретін параметрлер және авторизация өрістерінің пароль менеджеріне арналған параметрлері тексерілді. Барлық тексеру бөлек аккаунттар мен сынақ дерекқорында жүргізілді; негізгі `tab.sqlite3` пайдаланылмады.

## Клуб эмодзилері және раунд белгілері

Әр турнирде `club_emojis` сәйкестігі сақталады: бір клубтың барлық фракциясына бір эмодзи беріледі. 64 дайын эмодзи бар; бос эмодзи болғанда басқа клубқа бөлек белгі тағайындалады. Тізім толық таусылғаннан кейін ғана қайталануға рұқсат етіледі. Клуб тізімнен алынса да сәйкестік сақталады, сондықтан қайта қосылғанда белгі өзгермейді. Клуб өрісін бос қалдыруға болады; клубсыз фракция эмодзисіз көрсетіледі.

Бұрынғы турнир ашылғанда жетіспейтін эмодзилер SQLite транзакциясында бір рет толықтырылады. Бұл тек көрініс метадерегі: турнир қадамдары, раундтар, нәтижелер мен экспорт токені сақталады. Эмодзилер фракциялар тізімінде, жеребеде, нәтиже терезесінде және екі рейтингтегі фракция атауының алдында көрсетіледі.

АПФ: жасыл шеңбердегі ақ ✓ немесе қызыл шеңбердегі ақ × және екі спикердің жиынтық балы. Автожеңістің қолжетімді атауы мен tooltip мәтіні — «Автожеңіс». БПФ: 1 — екі жоғары жасыл белгі; 2 — бір жоғары көк белгі; 3 — бір төмен сары белгі; 4 — екі төмен қызыл белгі. Ранг астында жиынтық балл, енгізілмеген раундта — сызықша. Белгілер CSS және SVG арқылы боялады. Ұпай есептеу, рейтингті сұрыптау және Excel-дегі бастапқы атаулар мен ұпайлар сақталған.

Тексеру: 11 серверлік тест өтті. Жаңа тесттер эмодзидің сақталуын, ескі турнирді бір рет толықтыруды, бос клубты, тізім таусылғанға дейін бірегейлікті және Excel мұрағатындағы барлық файл мазмұнының өзгермегенін тексереді.

Chrome сценарийі:

```sh
TAB_DB=/private/tmp/tebikoshka-emojis.sqlite3 PORT=8019 python3 app.py
# Playwright орнатылған Python ортасында, екінші терминалда:
python tests/browser_emojis_check.py
```

Бөлек екі раундтық АПФ және БПФ турнирлерінде тексерілді: клуб ұсынысын таңдау, бір клубтың екі фракциясына ортақ эмодзи, басқа клубтың бөлек белгісі, жаңарту/қайта кіру/жаңа раундтан кейін сақтау, клубсыз фракция, жеребе мен екі рейтингтегі атаулар, ағымдағы/қорытынды рейтингтердегі барлық белгілердің бағыттары мен түстері, автожеңістің қолжетімді атауы, әр раундтың жиынтық балы және бос раунд сызықшасы. 390 px экранда бет көлденең асып кетпейді; кестелер өз ішінде айналады. JavaScript қатесі жоқ. Скриншоттар: `artifacts/emoji-*.png`. Негізгі дерекқор бұл тексерулерде пайдаланылмады.

## Клуб ұсынысын және нәтижелер кестесіндегі эмодзиді түзету

«Фракция қосу» және «Фракция өңдеу» формасы мен клуб өрісінде `autocomplete="off"` қойылды. HTML `datalist` қолданылмайды; тек осы турнирдегі клубтарды ұсынатын бір сайт тізімі бар. Клубтар бос орындардан тазартылып, қайталанбайды; бұрынғы клубты таңдауға және жаңа атауды қолмен жазуға болады.

`teamName(id)` барлық көріністе фракция идентификаторы бойынша бастапқы фракцияны тауып, клубтың сақталған эмодзиін атаудың алдына қосады. Бұл «Раунд · Нәтижелер» кестесінің барлық АПФ/БПФ позицияларына, баптаудағы тізімге, жеребеге, нәтиже терезесіне және екі рейтингке қолданылады. Сақталған атау өзгермейді. Ескі клубтарға эмодзиді бір рет тағайындап сақтау серверде бұрынғы тәртіппен орындалады.

`tests/browser_emojis_check.py` кеңейтілді: Chrome-да қосу/өңдеу кезіндегі жалғыз ұсыныс тізімі, автотолтыруды өшіру параметрлері, datalist болмауы, қайталанбайтын клубтар және жаңа атауды қолмен жазу тексерілді. Үш бөлек турнирде (3 және 4 фракциялық АПФ, 4 фракциялық БПФ) расталған нәтижелер кестесінің әр позициясы бетті жаңартуға дейін/кейін тексерілді. Бір клубтың екі фракциясы бірдей белгі қолданады; атауы бірдей, клубтары бөлек фракциялар әрқайсысының ID-і бойынша өз белгісін көрсетеді. Ағымдағы/қорытынды рейтингтер де өтті. JavaScript қатесі жоқ. 11 серверлік тест өтті. Барлық тексеру уақытша сынақ дерекқорында жүргізілді.

Жеке сынақ сервері үшін URL-ді өзгертуге болады:

```sh
TAB_DB=/private/tmp/tebikoshka-club-fixes.sqlite3 PORT=8020 python3 app.py
```

## Баптау беттеріндегі «Белгісіз әрекет» қатесі

Python сервері іске қосылғанда кодты жадқа жүктейді, ал JavaScript файлдары әр сұрауда дискіден оқылады. `app.py` өзгерген соң ескі процесті тоқтатып, серверді қайта іске қосыңыз, содан кейін браузерді жаңартыңыз. Жаңа интерфейс пен ескі сервер араласқанда `/api/settings`, `/api/setup_back`, `/api/finish_registration` сұраулары `400 {"error":"Белгісіз әрекет"}` қайтаруы мүмкін. Интерфейс енді `/api/state` жауабындағы `setup_api_version` арқылы сәйкестікті тексеріп, серверді қайта іске қосу туралы нақты хабарлама көрсетеді.

Тіркеуді браузерде қайта тексеру (жаңа сынақ аккаунттары; қолданыстағы турнирлер өшірілмейді):

```sh
# Playwright және Chrome бар Python ортасында:
TEBIKOSHKA_TEST_URL=http://127.0.0.1:8000 python tests/browser_registration_check.py
# URL көрсетілмесе, уақытша дерекқор мен жеке сервер қолданылады.
```

Сценарий баптауларды сақтау, екі «Артқа» батырмасы, екі қойынды, 47/48 фракция, 11/12 төреші, бос High/Low, БПФ бірінші жеребесі және бұрынғы құрылымдағы сақталған АПФ турниріне қайта кіру/автожеңіс/бірінші жеребені тексереді. Навигация сұрауларының әдісі, URL, JSON және жауаптары `artifacts/registration-network.json` файлына жазылады.

## Клэш

«Фракция қосу» және «Фракция өңдеу» формасындағы «Клэш (міндетті емес)» өрісіне төрешілердің толық аты-жөнін үтірмен бөліп жазыңыз. Фракцияны төреші тіркелмей тұрып сақтауға болады. Бос өріс рұқсат етіледі, ескі фракциялар бос өріспен ашылады.

Төреші румға тағайындалғанда сол румдағы фракциялардың клэш тізімі тексеріледі. Бас-кіші әріп пен артық бос орындар ескерілмейді; толық аты-жөні сәйкес келуі керек. Қызыл **!** белгісін меңзермен қарағанда немесе басқанда нақты төреші–фракция жұбы көрсетіледі. Белгілер сүйреп апарғанда, тізімнен таңдағанда, төрешіні босатқанда және фракцияны ауыстырғанда бірден жаңарады. Клэш — ескерту: жеребені растауға болады. Нәтиже енгізу мен рейтинг беттерінде белгілер көрсетілмейді.

Оқшауланған браузер тексерісі (Playwright және Chrome қажет):

```sh
python tests/browser_clash_check.py
```

Тексеру клэш тізімін төрешіден бұрын сақтау/өңдеу/қайта ашуды, бос және ескі өрістерді, толық есімді салыстыруды, бір төрешінің екі фракциямен клэшін, нақты сүйреп апаруды, тізімнен таңдауды, сервер жауабына дейін белгінің шығуын, фракцияны ауыстыруды, босатуды, қайта тағайындауды және клэшпен жеребені растауды қамтиды. Скриншоттар: `artifacts/clash-draw.png`, `artifacts/clash-results.png`.

Плей-оффсыз баптау мен бұрын плей-офф белгіленген турнирді аяқтауды браузерде тексеру:

```sh
python tests/browser_finish_check.py
```

Бұл сценарий уақытша дерекқорда жаңа баптауларды өріссіз сақтауды, `playoff=true` болып сақталған сынақ турнирін жалғастыруды, соңғы нәтижелерді енгізуді және бөлек растаусыз Excel жүктеуді тексереді.
# Деплой на Vercel

1. Импортируйте `muhammedjanserik/TEBIKOSHKA` в Vercel → **Add New → Project**.
2. Выберите **Framework Preset: Other**, корень проекта — `./`. Build Command и Output Directory оставьте без переопределений. Python 3.12 указан в `.python-version`; зависимости устанавливаются из `requirements.txt`.
3. Создайте PostgreSQL (например, через Vercel Marketplace). В SQL-редакторе базы выполните [schema.sql](schema.sql) один раз.
4. В **Settings → Environment Variables** добавьте `DATABASE_URL` — строку подключения PostgreSQL, желательно pooled URL с TLS (`sslmode=require`). Задайте её для нужных окружений; для Preview используйте отдельную тестовую базу.
5. Нажмите **Deploy**. Если переменная добавлена после деплоя, сделайте **Redeploy**. Проверьте регистрацию, создание турнира и сохранение после обновления страницы.

Запросы обслуживает `api/index.py`, маршрутизация настроена в `vercel.json`. Аккаунты, сессии и турниры хранятся в PostgreSQL: локальный SQLite не подходит для постоянного хранения в функциях Vercel ([документация](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel)). Без `DATABASE_URL` на Vercel API вернёт ошибку, чтобы не создавать временную базу с потерей данных.

Локально достаточно `python3 app.py`: без `DATABASE_URL` используется SQLite. Для локальной проверки PostgreSQL установите `python3 -m pip install -r requirements.txt`, выполните `schema.sql` и задайте `DATABASE_URL` в окружении. `.env` автоматически не загружается; `.env.example` служит образцом. Текущий `tab.sqlite3` не отправляется в Git и автоматически в PostgreSQL не переносится; новая база изначально пустая.

`artifacts/`, локальные базы, секреты и виртуальные окружения исключены из Git/деплоя. После подключения GitHub к Vercel новые push в production-ветку запускают деплой автоматически.
